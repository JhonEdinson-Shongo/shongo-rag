El problema

Un modelo sin tus documentos adivina con seguridad

Un LLM aprendió de textos públicos hasta cierta fecha. No conoce las políticas de tu tienda, y cuando no sabe, puede responder algo plausible pero falso. RAG cambia el orden: primero busca, después responde.

Sin RAG

Pregunta: ¿Cuánto tarda el envío a Medellín?

“Normalmente entre 5 y 7 días hábiles, según la transportadora.”

Suena bien, pero el número lo inventó. Nadie lo revisó contra la política real.

Con RAG

Pregunta: ¿Cuánto tarda el envío a Medellín?

“Medellín no aparece por nombre, pero la política dice que a otras ciudades tardan 3 a 5 días hábiles. [1]”

Busca el párrafo correcto, responde con él y cita la fuente para que puedas verificarlo.

Paso 01 · Ingesta

El archivo se convierte en fragmentos

Un PDF, un Word o una página web primero se convierten en texto plano. Luego el texto se parte en fragmentos (chunks): son la unidad que el sistema recupera después. Si son muy grandes traen ruido; si son muy pequeños pierden contexto.

  1. 1 Extraer el texto del archivo
  2. 2 Limpiar espacios y saltos de línea
  3. 3 Partir en fragmentos con solapamiento

¿Por qué solapar? Sin solapamiento, una frase que cae justo en el corte queda repartida y ningún fragmento la tiene completa. Repetir un poco de texto a propósito evita ese hueco.

Dimensiones reales: un modelo real genera entre 384 y 3 072 números, aprendidos de millones de textos. Aquí son 8 conceptos escritos a mano para que se puedan leer.

Regla de oro: el mismo modelo para los documentos y para las preguntas. Si cambias de modelo, hay que volver a calcular todos los vectores.

Paso 03 · Almacenamiento

Cada fragmento se guarda como un registro

La base de datos no guarda solo el texto. Guarda el vector para buscar por cercanía, una huella (hash) para detectar cambios y el nombre del modelo, para no mezclar vectores que no se pueden comparar.

CREATE TABLE fragmentos (
  id          TEXT PRIMARY KEY,          -- identifica la fila
  documento   TEXT NOT NULL,                 -- de qué archivo viene
  hash_sha256 CHAR(64) NOT NULL,             -- huella: detecta cambios
  modelo      TEXT NOT NULL,                 -- qué modelo generó el vector
  texto       TEXT NOT NULL,                 -- lo que leerá el LLM
  embedding   VECTOR(8) NOT NULL,            -- los números (1 024–3 072 en la vida real)
  creado_en   TIMESTAMPTZ DEFAULT now()
);

Paso 04 · Consulta

La pregunta pasa por el mismo modelo

No buscamos palabras exactas. La pregunta se convierte en vector con el mismo modelo que los fragmentos. Así, “¿cuánto demora el despacho?” encuentra el párrafo de envíos aunque no comparta ninguna palabra.

Si la pregunta se calculara con otro modelo, sus números no significarían lo mismo que los de la base de datos. Por eso cada fila guarda el nombre del modelo.

    Otras fórmulas para medir distancia

    La demo usa el coseno, que es el más común en RAG. Pero existen otras formas de medir qué tan parecidos son dos vectores (listas de números), y cada una responde una pregunta distinta. Estas son las más usadas:

    Manhattan (L1)

    Σ |aᵢ − bᵢ|

    Qué mide: Suma de las diferencias en cada dimensión, como contar las cuadras que recorres en una cuadrícula.

    Cuándo: Cuando no quieres que una sola diferencia muy grande domine el resultado.

    Minkowski (Lp)

    (Σ |aᵢ − bᵢ|ᵖ)^(1/p)

    Qué mide: Es una familia de fórmulas. Con p = 1 da Manhattan; con p = 2, la euclidiana.

    Cuándo: Cuando quieres ajustar cuánto pesan las diferencias grandes.

    Chebyshev (L∞)

    máx |aᵢ − bᵢ|

    Qué mide: Solo mira la diferencia más grande entre dos dimensiones.

    Cuándo: Cuando ninguna dimensión debe estar muy lejos de la otra.

    Distancia angular

    arccos(coseno)

    Qué mide: Mide el ángulo entre los dos vectores. 0 = misma dirección.

    Cuándo: Cuando necesitas una distancia que cumpla todas las reglas matemáticas, por ejemplo para agrupar. Nota: 1 − coseno parece igual, pero no las cumple.

    Jaccard

    |A ∩ B| / |A ∪ B|

    Qué mide: Qué parte de los elementos comparten dos conjuntos. 1 = idénticos, 0 = nada en común.

    Cuándo: Búsqueda por palabras o etiquetas exactas, no por significado.

    Hamming

    número de posiciones distintas

    Qué mide: Cuenta cuántos bits (0 o 1) son diferentes.

    Cuándo: Vectores binarios, muy comprimidos, que se comparan rápido.

    Cuál usa esta demo: el coseno. Con vectores normalizados (de longitud 1), el coseno, el producto punto, la euclidiana y la angular dan el mismo orden de resultados.

    Paso 06 · Respuesta

    El prompt se arma con lo encontrado

    El modelo no recuerda tus documentos. Recibe un prompt con tres partes: las instrucciones, el contexto (los fragmentos que pasaron el filtro, numerados) y la pregunta. Redacta la respuesta con ese contexto y cita sus fuentes.

    Ilustrativo: aquí no llamamos a ningún LLM. La respuesta toma la frase de los fragmentos más parecida a la pregunta. Si una frase aparece cortada (…), la continuación está en el fragmento siguiente: por eso importa el solapamiento del paso 01.

    Mapa completo

    El viaje completo, de un PDF a una respuesta

    1. 01 · Archivo: el PDF, Word o página web pasa a texto plano.
    2. 01 · Fragmentos: el texto se parte en fragmentos con solapamiento.
    3. 02 · Embedding: cada fragmento se convierte en un vector con el modelo.
    4. 03 · Base de datos: se guarda id, hash, modelo, texto y vector.
    5. 04 · Pregunta: la pregunta se convierte en vector con el mismo modelo.
    6. 05 · Proximidad: coseno, top-k y umbral eligen los fragmentos.
    7. 06 · Prompt: instrucciones, fragmentos numerados y la pregunta.
    8. 06 · Respuesta: el modelo responde con citas, o dice que no lo encuentra.

    Errores comunes

    • • Fragmentos gigantes: mucho ruido y la búsqueda pierde precisión.
    • • Cambiar de modelo sin recalcular: los vectores viejos ya no son comparables.
    • • No guardar el hash: recalculas todo cada vez que cambia una coma.
    • • Umbral en cero: el modelo responde aunque los fragmentos no tengan nada que ver.
    • • Respuestas sin cita: sin fuente no hay forma de verificar nada.

    Para llevarlo a producción

    • • Base vectorial real: pgvector, Qdrant o similar, con índice HNSW para millones de fragmentos.
    • • Modelo de embeddings real, el mismo para documentos y preguntas.
    • • Reranker: reordena los top-k con un modelo más preciso.
    • • Evaluación: preguntas con respuesta esperada para medir si el RAG mejora de verdad.
    • • Permisos: cada fragmento hereda quién puede verlo antes de entrar al prompt.
